# CIL 字节码控制流重定向方案

## 1. 概述

绕过外层加壳启动 Unity 引擎后，必须在托管代码层解除 `XX.IN::Awake()` 的第二层环境拦截。

本方案采用精准的 CIL（Common Intermediate Language）字节码原地重定向技术，仅修改 34 个字节，不破坏程序集整体结构与元数据表。

## 2. 补丁目标与偏移分析

通过 PE 节区映射与反编译定位，补丁需在 `AliceInCradle_Data/Managed/unsafeAssem.dll` 中作用于三处关键位置：

### 2.1 核心环境检测重定向（`IN::Awake`）
- **文件物理偏移**：`0xf9d53`
- **原始逻辑**：检测全部完成后在 IL 偏移 `IL_02a6` 处校验 `loc.0` 变量：
  ```cil
  IL_02a6: 06 2d 16  ; ldloc.0; brtrue.s IL_02d4
  ```
  若 `loc.0` 为 0 则顺序执行至 `IL_02be`，加载报错场景 `SceneCannotLaunch_InvalidEnviroment`。
- **修补逻辑**：无论 `loc.0` 为何值，将条件跳转指令修改为无条件短跳（`br.s`），直接跳过整个报错场景加载块，并在后续指令槽填入 `nop`（空操作）：
  ```cil
  IL_02a6: 2b 17     ; br.s IL_02d4 (强制跳过报错加载逻辑)
  IL_02a8: 00 ... 00 ; 连续填充 23 字节 NOP
  ```
- **字节比对**：
  - 原始字节（25 字节）：
    `06 2d 16 72 fe e3 00 70 28 65 0a 00 0a 02 28 89 00 00 0a 28 af 01 00 0a 2a`
  - 修补字节（25 字节）：
    `2b 17 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00`

### 2.2 敏感特性防劣化修补（`X::get_SENSITIVE` 与 `X::get_SP_SENSITIVE`）
- **文件物理偏移**：`0x13e1d0` 与 `0x13e1da`
- **修改目的**：使属性访问器直接返回安全默认值 `false`（`ldc.i4.0; ret`），规避依赖检测标志引发的二次属性异常。
- **字节比对**：
  - `get_SENSITIVE` 原字节：`26 7e 2a 1e 00 04 16 fe 02 2a` -> 修补为：`26 16 2a 00 00 00 00 00 00 00`
  - `get_SP_SENSITIVE` 原字节：`26 7e 2a 1e 00 04 17 fe 02 2a` -> 修补为：`26 16 2a 00 00 00 00 00 00 00`

## 3. 自动化修补引擎（`patch_unsafeAssem.py`）

本仓库提供了原地二进制补丁工具 `patch_unsafeAssem.py`，其执行流程具备以下安全特性：
1. **动态路径解析**：优先通过环境变量 `AIC_GAME_DIR` 读取游戏路径，同时支持命令行显式指定；
2. **字节指纹先验验证**：在写入任何字节前，严格校验原位置的特征序列，杜绝版本不匹配导致的损坏；
3. **自动备份机制**：首次修补自动在同目录下创建 `unsafeAssem.dll.orig` 纯净备份；
4. **幂等性保障**：若检测到文件已处于修补状态，平滑退出并给出通知。

```bash
# 执行本地自动化修补
python3 patch_unsafeAssem.py
```
